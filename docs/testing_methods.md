# Сравнительный анализ методов тестирования

## 1. Применённые методы

| Метод | Тип | Где применил |
| --- | --- | --- |
| Анализ причинно-следственных связей | чёрный ящик | `tests/test_quality.py` (C1..C8 → E1..E8) |
| Эквивалентное разбиение | чёрный ящик | `tests/test_student.py` (классы корректных/некорректных значений) |
| Анализ граничных значений | чёрный ящик | курс 0/1/6/7, оценка 1/2/5/6 |
| Покрытие операторов | белый ящик | `coverage` (100 %) |
| Покрытие решений (ветвей) | белый ящик | `coverage --branch` (98,8 %) |
| Покрытие условий | белый ящик | составные условия `bool(grades) and ...` |
| Комбинаторное покрытие условий | белый ящик | таблица решений T01–T07 |

## 2. Сравнение

| Метод | Достоинства | Ограничения | Рекомендации |
| --- | --- | --- | --- |
| Причинно-следственные связи | Проверяет комбинации условий; выявляет неполноту спецификации; каждая строка таблицы — готовый тест | Таблица быстро растёт (2ⁿ); слабо исследует границы | Применять к бизнес-правилам с несколькими флагами; дополнять граничными значениями |
| Эквивалентное разбиение | Резко сокращает число тестов; простая техника | Не проверяет сочетания классов; результат зависит от правильного выделения классов | Для каждого входного поля выделять корректные и некорректные классы |
| Граничные значения | Находит ошибки `<`/`<=` — самые частые | Не применим к неупорядоченным данным; не видит комбинаций | Всегда проверять min, min+1, max−1, max и значения за границами |
| Покрытие операторов | Легко измеряется; показывает «мёртвый» код | Не гарантирует проверку обеих ветвей `if` | Использовать как нижнюю планку |
| Покрытие решений | Каждая ветвь выполняется хотя бы раз | Не проверяет каждое подусловие составного выражения | Основная метрика в CI (`--branch`) |
| Покрытие условий | Каждое подусловие принимает 0 и 1 | Может не покрыть все решения | Комбинировать с покрытием решений (решения/условия) |
| Комбинаторное покрытие | Самый строгий критерий | Число тестов растёт экспоненциально | Только для критичных функций с 2–3 условиями |

## 3. Вывод

Ни один метод не достаточен сам по себе. Я использовал анализ
причинно-следственных связей как основу (он нашёл оба дефекта),
эквивалентное разбиение и граничные значения — для валидации полей,
а покрытие ветвей — как объективный критерий полноты. Такое сочетание
дало 83 теста, 99 % покрытия и 0 открытых дефектов.
